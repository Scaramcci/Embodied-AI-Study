# F3.1 从图像到人体关键点

## 1. F3 在整条流水线中的位置

```text
真实世界中的人
  -> 相机采集 RGB / depth
  -> 感知算法估计人体关键点、物体姿态和接触
  -> 结构化表示
  -> F2 重定向与 IK
  -> 机器人关节轨迹
```

F3 研究的是“机器人如何从传感器数据中获得可供后续算法使用的描述”。F2 使用的
`shoulder/elbow/wrist` 并不是相机天然输出的，而是感知算法根据图像估计出来的。

## 2. pixel、joint 与 keypoint

- pixel：图像网格中的一个位置，例如 `[u, v] = [620, 350]`；它只说明图像中的
  横向和纵向位置。
- joint：语义上的人体关节名称，例如 `left_elbow`。它不是机器人电机，也不一定是
  医学上精确的关节中心。
- keypoint：算法给某个语义点估计的位置。`left_elbow -> [620, 350]` 表示算法认为
  左肘出现在这个像素附近。

因此，图像中的 `elbow` 是一个带语义标签的观测，不是机器人肘关节角。

## 3. 2D 与 3D keypoint

### 2D keypoint

```text
positions.shape = [T, J, 2]
最后一维 = [u, v]，通常单位为 pixel
```

它告诉我们关节在画面的哪里，但不直接告诉我们离相机多远。同一个 `[u, v]` 可以
对应该视线上许多不同的三维点。

### 3D keypoint

```text
positions.shape = [T, J, 3]
最后一维 = [x, y, z]
```

它还必须说明：

- `frame`：坐标相对于相机、世界、人体 root，还是机器人 base；
- `unit`：metre、millimetre，或经过归一化的无量纲数；
- 3D 来源：depth 反投影、多相机三角测量，或单目模型估计。

`[x, y, z]` 本身没有完整意义；frame 和 unit 缺失时不能安全送入后续优化。

## 4. 时间与可信度字段

一个动作不是一张图，而是一串按时间排列的观测：

```text
positions  [T, J, D]   每帧每个关节的位置，D 为 2 或 3
confidence [T, J]      每个估计的可信程度
timestamps [T]         每帧对应的采集时刻
joint_names [J]        第 j 个位置属于哪个语义关节
frame                  坐标参考系
unit                   空间单位
```

- `confidence` 低：通常意味着遮挡、出画、模糊或模型不确定；低置信度不是坐标值为零。
- `timestamps`：用来判断真实时间间隔、丢帧、速度和多传感器同步；数组相邻不代表
  时间间隔一定相同。
- `joint_names`：防止把不同数据集的关节顺序误当成一致。

## 5. 从图像到机器人之前的四种对象

| 层级 | 例子 | 含义 |
|---|---|---|
| 原始传感器数据 | RGB 像素、depth 图 | 相机测到了什么 |
| 感知输出 | `left_wrist=[u,v]` | 算法认为人体点在哪里 |
| 结构化任务表示 | 相机系 3D 腕部轨迹 | 后续希望保留什么信息 |
| 机器人命令 | `q[t, dof]` | 电机最终执行什么 |

这四层不能直接混用。尤其是 2D wrist pixel 缺少深度、坐标系转换、尺度映射和机器
人约束，不能直接当作机器人目标或关节命令。

## 6. 论文阅读检查表

看到 “we extract human pose/keypoints” 时，立即检查：

1. 是 2D 还是 3D？shape 是什么？
2. joint 名称和顺序是什么？
3. frame 和 unit 是什么？
4. 3D 是实测、几何恢复，还是模型预测？
5. 是否保存 timestamp 和 confidence？
6. 遮挡、丢帧和低置信度怎样处理？

## 本课检查题

一段数据只有 `wrist[T, 2]`，数值是图像像素坐标。为什么它还不能直接成为机器人的
三维腕部目标？至少说出三个缺失的信息或处理步骤。
