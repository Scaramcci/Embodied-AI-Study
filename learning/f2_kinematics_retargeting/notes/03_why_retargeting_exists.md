# 为什么需要人体、相机和 IK

## 从任务开始，而不是从算法开始

假设目标是：一个人做出伸手动作，让机器人模仿其手臂运动。

机器人本身不知道人在做什么。系统需要依次解决：

```text
相机观察人
  -> 感知算法估计肩、肘、腕的位置
  -> 把人体动作转换成机器人应该完成的末端/肘部目标
  -> IK 寻找能完成目标的机器人关节配置
  -> 检查候选配置
  -> 控制器才可能让实机运动
```

人体不是所有机器人任务的必需输入。这里只使用人体，是因为研究问题是
human-to-robot motion retargeting 或 teleoperation。如果目标由鼠标、程序、语言或
路径规划器提供，就可以没有人体和相机。

## 相机的作用

相机是传感器，提供图像或深度数据。感知算法从中估计人体关键点。相机输出的
不是机器人关节命令，而是对外部世界的观测，而且带有 frame、单位、噪声、遮挡、
置信度和延迟。

## 人体的作用

人体在这里充当动作示范者或操作者。系统通常不复制人的关节角，而是从动作中
提取意图，例如“手腕到哪里”“肘部朝哪边”“手掌朝向哪里”。这些意图经尺度和
坐标对齐后成为机器人的 task-space target。

## IK 的作用

机器人最终需要自己的关节配置。IK 接收目标和机器人模型，搜索一个候选 `q`，
使 `FK(q)` 尽量接近目标，同时满足已加入的约束。

```text
目标：“机器人手到这里”
             ↓
IK：“哪些机器人关节角能做到？”
             ↓
候选 q
```

IK 不负责观察人体，也不负责驱动电机；它只解决目标与机器人几何配置之间的逆向
映射。

## FK 回代的作用

IK 返回候选 `q` 后，把它重新输入 FK：

```text
target -> IK -> q_candidate -> FK -> achieved pose
                                   ↓
                         与 target 比较误差
```

这类似机器学习中把模型输出重新代入评价函数。它验证“这个候选关节配置在同一
机器人模型下实际对应什么末端 pose”。它不能验证碰撞、动力学或实机误差，除非
这些另有专门模型和检查。

## 三类检查不要混淆

- **FK 回代**：末端是否到达目标；
- **碰撞检查**：机器人 link 的几何体是否与自己或环境重叠；
- **轨迹连续性检查**：相邻时刻的关节配置是否发生不合理跳变，并进一步检查速度
  和加速度。

一个候选解可能 FK 误差很小，但同时发生碰撞；也可能每一帧都准确，却在相邻帧
之间从一个 IK 解突然切换到另一个解。
