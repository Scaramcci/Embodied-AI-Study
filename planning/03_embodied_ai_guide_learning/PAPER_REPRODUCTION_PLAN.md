# 论文小规模复现计划

> 建立日期：2026-08-30  
> 硬件基线：32 GB RAM、NVIDIA GeForce RTX 4090 Laptop GPU（16 GB VRAM）  
> 目标：至少完整走通一次 `环境 -> 数据 -> 训练 -> checkpoint -> 评测 -> 消融 -> 报告`，不追求复刻论文的全部硬件和实验规模。

## 1. 复现策略

本计划区分两种性质不同的工作：

1. **作者代码小规模复现**：使用论文作者公开仓库，缩小数据量和训练轮数，验证代码、损失、训练与评测链路。
2. **方法级复现**：论文没有公开代码或完整系统依赖真实机器人时，自行实现核心几何/优化思想，并明确标为简化实验。

所有报告必须分开记录：

- 论文作者报告的数值；
- 本机实际复现的数值；
- 与原论文不同的数据、模型、训练轮数和硬件；
- 为兼容当前环境所做的代码修改。

## 2. 主复现：DexTele 官方代码的小规模训练

### 2.1 可行性结论

DexTele 的[官方项目页](https://3469627147abc.github.io/DexTele/)提供了[公开代码仓库](https://github.com/ZaynLeung/Robotelop)。仓库包含训练入口、配置、模型、数据目录和测试入口，因此适合用来真正走通一次训练流程。仓库说明较简略，正式训练前必须先做依赖与数据审计。

16 GB 显存足以尝试缩小后的图网络训练，但具体 batch size 不能预先假定；以第一次显存探测结果为准。系统内存只有 32 GB，数据加载器 worker 和缓存也应保守设置。

### 2.2 启动时机

- Phase 2：只阅读仓库结构，不安装、不训练；
- 完成 Phase 3 的 graph retargeting、复合 loss 与轨迹指标后：开始 R0–R3；
- Phase 6：整理完整复现报告，并与论文实验表对照。

### 2.3 实施步骤

#### R0：冻结复现对象

- 记录论文版本、仓库 URL、commit hash、许可证和审计日期；
- 新建隔离环境 `eai-dextele-repro`，不污染当前 `eai-retarget`；
- 根据仓库实际兼容性确定 Python、PyTorch、CUDA 和 PyG 版本，不提前硬编码；
- 保存环境清单和所有兼容补丁。

通过标准：能导入模型、数据集和损失模块，并确认 CUDA 可用。

#### R1：数据与前向 smoke test

- 审计仓库自带 `sign-all` 等数据的格式、数量、单位、划分与许可；
- 固定一个很小的 train/test 子集，并保存样本清单和随机种子；
- 用 batch size 1 跑通 `dataset -> model forward -> loss -> backward`；
- 记录一次输入/输出 shape、loss 各项和峰值显存。

通过标准：一个 batch 可以完成反向传播，无 NaN，checkpoint 能保存并重新载入。

#### R2：短程训练闭环

第一轮只追求端到端成功：

- 优先使用 arm-only 或仓库最稳定的默认任务；
- 使用固定小子集，例如完整数据的 5%–10%，实际数量在数据审计后确定；
- 先跑 2–3 epoch 验证稳定性，再跑约 10–30 epoch；
- 从 batch size 4 或更小开始，按实测显存调整；
- 保存训练/验证 loss 曲线、最佳 checkpoint、耗时和峰值显存；
- 用仓库测试入口或等价脚本完成一次定量评测与可视化。

通过标准：训练 loss 有可解释趋势，模型可从 checkpoint 恢复，测试结果能够重复得到。

#### R3：一个受控消融

只做一个最能对应论文主张的改动，候选顺序：

1. 去掉或降低一个关键几何 loss；
2. 去掉 graph refinement/相关模块；
3. 对比不同训练数据比例。

只改变一个变量，保持 seed、数据子集、epoch 和评测方法一致。若官方仓库接口不支持可靠消融，就停止在 R2，不为了“做消融”大幅重写作者代码。

### 2.4 明确不做

- 不复现全部机器人平台和真实遥操作硬件；
- 不优先配置 FrankMocap 等老旧视觉依赖；
- 不追求论文完整数据规模、全部指标或完全相同数值；
- 不把缩小训练结果描述成论文完整结果的验证。

## 3. 次复现：ObjRetarget 核心方法的简化实现

### 3.1 可行性结论

截至 2026-08-30，[ObjRetarget 官方项目页](https://3469627147abc.github.io/ObjRetarget/)和[arXiv 页面](https://arxiv.org/abs/2607.03828)未提供公开代码入口，因此暂不计划声称“作者代码复现”。本项目改做与论文主张直接对应的方法级实验。

### 3.2 启动时机

- 完成 Phase 3 后：复现手臂轨迹优化；
- 完成 Phase 4 的 contact geometry 后：加入简化多面体手部模型；
- Phase 6：完成消融、图表和局限说明。

### 3.3 实验 A：拟人手臂约束

在 PyBullet 或数值运动学中，以整段 `q[0:T]` 为优化变量，组合：

```text
末端位置/姿态误差
+ arm-plane 或肘部方向约束
+ joint-limit penalty
+ temporal smoothness
```

对比 baseline、去掉 arm-plane、去掉 smoothness 三种设置。记录 FK 任务误差、关节速度/加速度、限位余量和 arm-plane 偏差。

### 3.4 实验 B：简化接触几何

使用合成物体点云、掌心和若干指尖构造局部多面体/边关系，不接真实灵巧手。比较：

- 只跟随指尖绝对位置；
- 加入 object-relative 几何；
- 去掉局部多面体约束。

记录接触点距离、边长/相对位姿误差、接触保持率以及简化滑移代理指标。该实验验证的是几何思想，不验证真实摩擦、力控制或硬件成功率。

### 3.5 代码发布状态复查

进入 Phase 6 前再次检查官方项目页。若作者后来发布代码，先审计依赖、数据和许可证，再决定是否把实验切换为官方实现；不在中途盲目推翻已经完成的方法级实验。

## 4. 最终交付物

至少完成 DexTele R2；若作者仓库因数据或兼容性无法合理运行，则完整保留审计证据，并以 ObjRetarget 方法级实验 A+B 作为主要复现。

最终目录应包含：

```text
reproduction/
  README.md                 # 复现范围、原论文与本实验差异
  environment/             # 环境清单与版本
  data_manifest/           # 子集、划分、seed
  configs/                 # 小规模训练与消融配置
  checkpoints/             # 最佳模型或下载说明
  outputs/                 # 曲线、指标、可视化
  REPRODUCTION_REPORT.md   # 结果、失败、局限和结论
```

完成 Gate：能够用一条明确命令重新启动训练，用 checkpoint 重新评测，并解释每项指标为何能或不能支持论文主张。

## 5. 风险与停止条件

- 显存不足：依次减小 batch、序列长度和模型规模，必要时使用梯度累积；不默认混合精度不会破坏旧代码。
- 系统内存不足：降低 worker、关闭全量内存缓存、缩小数据子集。
- 依赖老旧：优先做最小兼容补丁并记录；若需要大规模重写，转为方法级复现。
- 缺少训练数据或许可不清：不自行抓取来源不明数据；使用仓库明确提供的数据或合成数据。
- 连续排障超过一个学习单元仍无法完成单 batch：停止追逐完整作者环境，提交可复现的失败审计并执行备用实验。
